# FC EXICAN 운영 허브

주간 참석 투표부터 매칭 후보, 키퍼·휴식 배정, 장부와 개인 기록까지 관리하는 풋살팀 운영 허브입니다.

**사용하기:** https://coldclosewin-design.github.io/futsal-rotation/

## 팀원용 사용법

1. 홈에서 팀 PIN으로 로그인합니다. PIN은 회장에게 별도로 전달받고, 투표 화면에서 내 이름을 선택합니다.
2. **이번 주 투표**에서 참석 또는 불참을 선택합니다. 월요일 13:00 마감 전에 응답하세요. 홈의 **투표 링크 복사**로 카카오톡에 안내를 붙여넣을 수 있습니다.
3. **매칭 후보**에서 일정을 확인하고 원하는 후보에 👍를 누릅니다. 홈의 **후보 공유**는 추천 상위 3건의 일정·제목·카페 링크를 복사합니다. 복사를 지원하지 않는 브라우저에서는 문구 선택 창이 열립니다.
4. **내 현황**에서 내 이름을 선택하면 납부·미납, 벌금, 참석률과 키퍼·휴식 기록을 볼 수 있습니다. 선택한 이름은 해당 기기에 저장됩니다.
5. 간식을 대신 구매했다면 **장부 → 간식 청구**에서 금액과 내용을 제출합니다. 회장이 승인하면 장부에 반영됩니다.

막히면 더보기 → 도움말을 확인하세요.

`?demo=1`을 붙이면 샘플 데이터로 체험할 수 있습니다. 데모 변경은 메모리에서만 유지되므로 새로고침하거나 다른 탭을 열면 초기화됩니다. 홈의 링크와 공유 문구에도 데모 표시가 유지됩니다.

## 회장용 주간 운영

| 시점 | 할 일 |
|---|---|
| 일요일 13:00 이후 | Cron이 다음 토요일 투표를 자동 생성합니다. 홈에서 투표 링크를 복사해 공유합니다. |
| 월요일 13:00 이후 | 투표가 마감되고 미응답·늦은 투표 벌금이 자동 처리됩니다. 실행은 해당 시각 이후 Cron 작업이 시작될 때 이루어집니다. |
| 주중 | 매칭 후보를 확인하고 문자로 연락한 뒤 연락 상태를 기록합니다. 합의한 날짜·시간·구장·구장비로 매치를 확정합니다. |
| 공휴일·이벤트 경기 | **투표** 또는 **관리 → 투표 → 투표 만들기**에서 특별 투표 만들기: 날짜·제목·마감(한국 시간)·미투표 벌금 적용 여부를 정합니다. 팀원은 투표 전환 칩에서 각각 응답합니다. |
| 토요일 경기 전 | **배정표**에서 투표 참석자를 불러오고 참가 구간을 확인한 뒤 배정합니다. 저장한 배정 기록은 개인 페이지에서 조회할 수 있습니다. |
| 경기 후 | **관리**에서 출석·지각·불참과 벌금을 확인하고 구장비를 기록합니다. 간식 청구를 승인하고 입금 내역을 장부에 반영합니다. |
| 월초 | 설정된 장부 시작 월부터 월 회비가 자동 생성됩니다. 납부와 회장·부상 감면 내역을 확인합니다. |

회장 작업은 별도의 회장 계정으로 로그인해야 합니다. 일반 팀 로그인으로는 관리 데이터를 수정할 수 없으며, Supabase RLS가 쓰기 권한을 검사합니다. 홈의 공유 버튼은 팀원도 사용할 수 있습니다.

구장비 중복 입력은 화면에서 먼저 확인하지만, 현재 DB의 NULL 멤버 행 제약은 동시에 제출되는 중복까지 막지 못합니다. 같은 매치의 구장비는 한 명이 기록하고 장부에서 확인하세요.

## 화면 구성

모바일에서는 하단 탭바, 900px 이상에서는 왼쪽 레일로 이동합니다. 내 현황·회칙·관리는 모바일의 **더보기**에 있습니다. 화면은 흑연 보드의 핵심 수치, 간유리 작업 패널, 행 목록 순서로 읽습니다. 자세한 규칙은 [DESIGN.md](DESIGN.md)를 참고하세요.

- **투표**: 참석 인원·마감·가능 포맷을 보드에서 확인하고 참석/불참을 선택합니다. 진행 중인 투표와 미투표 팀원만 점등합니다.
- **매칭**: 기본 필터 후보 수와 최근 24시간 새 후보를 표시합니다. 필터·추천·연락 상태와 매치 확정은 기존 기능을 유지합니다.
- **장부**: 팀 잔액·월 미납·지출을 보드에서 확인합니다. 미납이 있는 셀만 점등하며 멤버 행을 펼쳐 상세 항목을 확인합니다.
- **배정표**: 선택한 참가자 수·포맷·최소 인원·연동 상태를 표시합니다. 생성 후 다시 섞기·카톡 복사·회장 저장 순서로 사용합니다.
- **내 현황**: 이번 달 미납액과 참석·투표 참여율·키퍼 누적을 요약하고 벌금과 배정 기록을 행 목록으로 보여줍니다.
- **관리**: 다음 매치 D-day, 대기 간식 청구, 출석 미입력 완료 경기 수를 확인합니다. 출석 미입력은 저장된 출석 행이 아직 없는 완료 경기입니다.
- **회칙**: 보드 없이 회비·벌금 요약과 경기 기록을 행 목록으로 표시하며 회칙 전문은 그대로 제공합니다.
- **도움말**: 로그인 없이 처음 사용법·매주 할 일·회장 운영 순서와 문제 해결 방법을 확인합니다.

취소·거절·벌금 기록 버튼은 다른 동작 아래에 점선 버튼으로 분리합니다. 데모의 새 후보 표시 시각은 픽스처 내 수집 시각(없으면 작성 시각)의 간격을 보존해 현재 기준으로 옮기므로 오래된 샘플에서도 점등을 확인할 수 있습니다. 라이브에서는 실제 수집 시각을 사용합니다.

## 설정값

공용 설정은 [`js/config.js`](js/config.js)에서 관리합니다. 아래에는 설정 이름과 용도만 기재하며 인증 정보의 실제 값은 기재하지 않습니다.

| 키 | 용도·기본 정책 |
|---|---|
| `TEAM_NAME` | 화면과 공유 문구의 팀 이름 |
| `SMS_TEMPLATE` | 후보 연락 문자. `{제목}`, `{팀명}`, `{날짜}`, `{시간}`, `{구장}`, `{인원}`, `{포맷}`을 치환 |
| `SUPABASE_URL` | 연결할 Supabase 프로젝트 URL |
| `SUPABASE_ANON_KEY` | 브라우저용 공개 키. RLS를 적용해야 하며 service role 키를 넣으면 안 됨 |
| `TEAM_EMAIL` | 팀 PIN 로그인에 사용하는 공용 Auth 사용자 이메일 |
| `ADMIN_EMAIL` | 회장 로그인에 사용하는 Auth 사용자 이메일. DB 권한 정책과 함께 일치시킬 것 |
| `FINES.LATE_VOTE` | 늦은 투표·미응답 벌금, 5,000원 |
| `FINES.NO_SHOW` | 불참 벌금, 10,000원 |
| `FINES.LATE` | 지각 벌금, 10,000원 |
| `FINES.LATE_KICKOFF` | 경기 시작 이후 지각 벌금, 30,000원 |
| `DUES_MONTHLY` | 월 회비, 30,000원 |
| `INJURY_EXEMPT_RATE` | 부상 기간 월 회비 감면 비율, 0.5 |
| `PRESIDENT_EXEMPT_MODE` | `week`: 회장 경기별 7,500원 감면, `month`: 회장 월 30,000원 감면 |
| `LEDGER_START_MONTH` | 회비 자동 생성 시작 월, `2026-11`. 이전 달은 기존 정산으로 마감 |
| `CAFE.CLUB_ID` | 수집 대상 네이버 카페 ID |
| `CAFE.MENUS` | 수집 대상 메뉴 ID와 지역 이름의 매핑 |
| `CAFE.ARTICLE_URL` | 게시글 ID·메뉴 ID를 받아 원문 링크를 만드는 함수 |
| `PREFERRED_START_HOURS` | 후보 추천 시 시작 시각 우선순위, 8 → 7 → 9 → 10시 |

## 운영 절차

### PIN·회장 비밀번호 분실

Supabase Dashboard의 **Authentication → Users**에서 해당 공용 사용자를 확인해 삭제한 뒤, 설정의 동일한 이메일로 사용자를 다시 생성합니다. 팀 PIN은 6자리 이상으로 정하고 이메일 확인 상태를 활성화합니다. 회장 비밀번호도 별도로 재설정한 뒤 해당 사용자에게 안전하게 전달합니다. 실제 값은 저장소·이슈·PR에 기록하지 않습니다.

`members`의 팀원 기록과 공용 Auth 사용자는 별개입니다. 기존 세션의 JWT는 사용자를 삭제해도 만료까지 유효할 수 있으므로 계정 복구 후 각 기기에서 로그아웃하고 다시 로그인하세요. 자세한 계정 관리는 [Supabase 사용자 관리 문서](https://supabase.com/docs/guides/auth/managing-user-data)를 참고하세요.

### 멤버 추가·탈퇴

[`admin.html`](admin.html)의 **멤버** 탭에서 새 멤버를 추가하거나 이름·가입일·부상 기간 등을 수정합니다. 탈퇴자는 삭제하지 않고 **활동**을 해제해 투표 대상에서 제외하고 기존 장부·출석·배정 기록을 보존합니다. `members.json`은 오프라인 배정용 폴백으로 유지하며, DB 멤버 수정과 자동 동기화되지 않습니다.

### Cron 확인

[GitHub Actions](https://github.com/coldclosewin-design/futsal-rotation/actions)에서 `cron.yml` 워크플로의 최근 실행과 수집·정산 로그를 확인합니다. 현재 예약은 매일 KST 06:00~24:00에 매시간 실행하며 GitHub 상황에 따라 지연될 수 있습니다. 수동 실행의 `dry_run`을 켜면 저장 없이 처리 대상을 점검합니다. GitHub Actions Secrets에는 `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`를 등록하며 브라우저 설정에는 서비스 키를 넣지 않습니다.

투표 생성·월 회비·벌금은 재실행에 대비한 중복 방지 규칙을 사용합니다. 미응답 벌금은 최근 14일 대상도 재확인하므로 실패 후 다음 실행과 장부를 함께 확인하세요.

### 데이터 백업

Supabase **SQL Editor**에서 다음 표를 각각 `select * from public.표이름;`으로 조회하고 결과의 **Export → CSV**로 내보냅니다: `members`, `polls`, `poll_votes`, `match_candidates`, `candidate_reactions`, `matches`, `match_attendance`, `ledger`, `snack_claims`, `rotation_history`.

조회 행 제한을 확인하고 `select count(*)` 결과와 내보낸 행 수를 비교합니다. 백업에는 개인정보가 포함될 수 있으므로 접근이 제한된 별도 위치에 보관하고 Git에 올리지 않습니다. CSV는 데이터 사본이며 인증 사용자·권한·함수까지 복원하는 전체 DB 백업은 아닙니다. 스키마는 `supabase/`의 SQL과 함께 관리합니다. SQL Editor 사용은 [Supabase 데이터베이스 안내](https://supabase.com/docs/guides/database/overview)를 참고하세요.

## 개발

빌드 도구 없는 HTML/CSS/JavaScript 프로젝트입니다. GitHub Pages가 `main` 루트를 그대로 배포합니다. Node.js 20 이상과 로컬 정적 서버가 필요합니다. 새 npm 의존성 없이 테스트를 실행합니다.

```text
index.html         운영 홈
vote.html          참석 투표
matches.html       매칭 후보·확정 매치
rotation.html      키퍼·휴식 배정
ledger.html        장부·간식 청구
member.html        개인 현황
rules.html         회칙
admin.html         회장 관리
js/                설정·인증·데이터 계층·순수 규칙·공유 문구
scripts/           카페 수집·자동 정산
supabase/          스키마·시드·적용 안내
test/              Node 회귀 테스트
docs/tasks/        발주서
.github/workflows/ 테스트·Cron
members.json       오프라인 배정용 멤버 폴백
```

```sh
npm test
python -m http.server 8765
```

로컬 홈은 `http://localhost:8765/index.html?demo=1`에서 확인합니다. 브라우저에서 375px 폭, 콘솔 오류, 공유 복사와 폴백을 점검합니다. 데모는 실제 인증·RLS·Cron의 운영 검증을 대신하지 않습니다. 실제 DB 적용과 배포 확인은 회장·운영 담당자가 수행합니다.

작업은 [AGENTS.md](AGENTS.md)의 발주서 1건 → 브랜치 1개 → PR 1개 절차를 따릅니다. PR에는 원문 수용 기준, 자동 테스트 결과, 수동 화면 확인과 가정을 적습니다. DB 설치·업그레이드는 [Supabase 적용 안내](supabase/README.md)를 따르세요.

## 배정 규칙

| 참가자 수 | 포맷 | 필드 인원(키퍼 포함) | 키퍼 | 휴식 |
|----------|------|----------------------|------|------|
| 6명 | 5v5 | 5 | 1 | 1 |
| 6명 | 6v6 | 6 | 1 | 0 |
| 7명 | 5v5 | 5 | 1 | 2 |
| 7명 | 6v6 | 6 | 1 | 1 |

기본 기준은 8쿼터입니다.
키퍼·휴식을 합친 out 배정은 참가 구간의 시작·끝과 out 사이의 필드 플레이 길이가 고르게 되도록 점수를 매깁니다.
연속 out 방지와 참가 쿼터 대비 횟수 공평성을 우선하며, 역할별 횟수와 out 간격도 함께 고려합니다.
횟수가 같은 후보는 마지막 out 이후 오래 뛴 선수를 우선하고, 같은 입력과 다시 섞기 횟수에는 같은 결과를 제공합니다.
개인 간격 점수가 1.0을 넘으면 결과에 `out 간격 편중` 경고와 해당 쿼터를 표시합니다.
