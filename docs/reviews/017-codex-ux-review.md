# 017 UX·디자인 검토 (Codex)

검토 일시: 2026-10-19 00:43~00:53 KST. 검토 기준: `main`의 `218ad69`(2026-10-18 변경 포함). 환경: Windows의 Codex 인앱 브라우저, CSS 뷰포트 **375×812 / 1280×900**, 로컬 `python -m http.server 8765 --bind 127.0.0.1`, 모든 앱 화면 `?demo=1`.

검토한 화면: 홈(`index.html`), 투표(`vote.html`), 매칭(`matches.html`), 배정표(`rotation.html`), 장부(`ledger.html`), 내 현황(`member.html`), 회칙(`rules.html`), 도움말(`help.html`), 관리(`admin.html`, 멤버·투표·매치 탭). 모두 두 폭에서 열어 상단과 스크롤 끝을 확인했다. 팀원은 조성훈, 회장은 안준호를 선택했다. Claude 보고서는 읽지 않았다.

## A. 요약 (10줄 이내)

- **먼저 모바일 핵심 정보를 앞으로 옮길 필요가 있다.** 장부 미납·배정표 필드·멤버 편집이 표 오른쪽에 숨는다(B01).
- **작은 삭제 타깃과 낮은 불참 대비를 우선 수정해야 한다.** 열 삭제 ×는 약 21×20px이고, 불참 글자는 흰 배경에서도 대비 약 3.22:1이다(B02~03).
- **회장 작업의 맥락을 유지해야 한다.** 저장하면 펼친 영역이 닫히고, 투표 취소·일괄 정산은 바로 적용된다(B04, B06~07).
- 발견 18건: 상 0건, 중 9건, 하 9건. 데모에서 핵심 작업이 끝까지 막히는 상 등급 장애는 재현하지 못했다.
- 참석 즉시 저장, 명확한 삭제 영향 건수, 동일한 패널 재질과 주 메뉴는 유지할 장점이다.
- 날짜 확대·참석 워시는 가독성을 높이지만 현재 디자인 문서의 허용 범위를 넓힌 변경이다. 구현 결함과 디자인 기준의 개정 필요를 구분했다.

## D. 잘 된 점

- **참석 저장의 피드백이 빠르고 명확하다.** 선택 상태·인원·멤버 그룹·토스트가 함께 바뀐다. 이후 개선에서도 별도 저장 단계를 추가하지 않아야 한다.
- **삭제 영향 설명이 구체적이다.** 지워질 투표/벌금 건수와 남을 매치를 구분하고, 자동 생성 창 안의 재생성까지 설명한다. 취소 해제 동작과 기록 유지도 확인했다.
- **기본 재질과 내비게이션이 일관된다.** 375px 하단 메뉴/더보기와 1280px 왼쪽 레일을 모두 사용할 수 있고, 같은 간유리 패널·잉크 버튼·점등 색을 유지한다. 일반 화면의 페이지 전체 가로 넘침은 없었다.
- **빈 상태와 실패 이유를 사용자 문장으로 알려 준다.** 후보 없음은 필터 변경, 열린 투표 없음은 생성 시점, 중복 매치 등록은 날짜·시각 확인을 안내한다.
- **장부와 출석에 검토 단서가 있다.** 받을 돈을 음수 미납과 구분해 쓰고, 출석 벌금은 사람·종류·금액을 미리 보여 주며 이미 있는 벌금은 중복 생성하지 않았다고 알려 준다.

## E. 확인하지 못한 것

- 실서버 팀 PIN·회장 로그인·세션 복원·RLS 및 연락처/계좌의 실제 권한 경계. 데모의 `로그인 필요` 표시는 인증된 운영 화면의 상태로 판정하지 않았다. 실계정이나 실제 연락처·계좌를 입력하지 않았다.
- 실제 카카오톡 iOS/Android WebView, OS 문자 앱·클립보드 권한, 느린 네트워크·오프라인·동시 편집, 스크린리더와 실기기 손가락 조작. 이번 검토는 지정 폭의 브라우저/DOM/화면 관찰이며 전체 WCAG 적합성 인증이 아니다.
- 일요일 자동 생성·월요일 자동 마감/벌금·매시간 수집·11월 1일 회비 생성·지연 실행 등 시간 경과와 서버 작업. 현재 시점의 표시와 관련 문구를 확인했으며 `D-1` 등 모든 시간 분기를 화면에서 재현한 것은 아니다.
- 정산된 벌금이 연결된 투표의 삭제 거부 토스트. 기본 데모에는 이 조합이 없고 페이지 간 변경이 공유되지 않으므로, 데이터 주입 없이 UI만으로 재현하지 못했다. 도움말과 `js/data.js` 조건은 별도로 확인했으며 이를 실서버 검증으로 대체하지 않는다.
- 데모 페이지 이동/새로고침은 저장 상태를 초기화한다. 그래서 매칭 → 배정 → 출석 → 장부를 하나의 영속 데이터로 연결한 검증은 아니며 각 단계의 데모 화면 결과를 확인했다. 관리의 장부 미리보기는 부모 화면 안에 별도 내비게이션까지 나타나는 데모 전용 표시이므로 운영 화면 결함으로 세지 않았다.
- 실제 운영팀의 30초 완료율, 오조작률, 야외 가독성, 금액 산식의 실데이터 대사. B17의 날짜 불일치도 데모 한정 관찰이다.
