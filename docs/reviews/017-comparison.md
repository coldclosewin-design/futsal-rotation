## 4. 판단이 갈린 것

- **심각도 체계**: Codex는 "데모에서 끝까지 막히는 것"만 상으로 두어 상 0건. Claude는 "벌금·돈이 잘못 붙는 흐름"을 상으로 둠. 운영 리스크 기준으로는 Claude의 B1·B3·B5가 실제로 돈과 연결되므로 먼저 처리할 가치가 있다.
- **디자인 규칙 충돌**: 둘 다 "구현 결함"과 "규칙 개정 필요"를 구분했고, 날짜 확대는 문서화·참석 초록은 양론·버튼 짝은 분리·×는 모달로 — 결론은 Claude 보고서 F 표의 권장안과 같다.

## 5. 018 발주 후보 (합의된 우선순위)

1. **S 묶음(팀원 안전)**: 공유 링크 투표 id(B1)·매치 poll_id 날짜 연결(B15)·배정표 requireTeam(B18)·불참 칩 대비(Codex B03)·토스트 이름/길이(B13/B19)·홈 "내 투표"(B14).
2. **M 묶음(회장 루프)**: 투표 취소 확인창 + 복구 안내(B2/B06)·펼침 상태 보존(B4/B04)·출석 폼 조건 완화 + 스코어 선택(B3)·구장비 장부 기록 체크(B5)·전부 정산 확인(Codex B07).
3. **디자인 정리(F 결정 후)**: DESIGN.md에 보드 헤딩 크기·보드 내 링크 예외 명시, 참석 칩 무채색, 취소 버튼 행 부품화 + 삭제 단독, 열 관리 모달, 날짜 표기 통일(Codex B13), 모바일 표 열 순서(Codex B01).
