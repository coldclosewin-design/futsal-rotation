# 017 UX·디자인 검토 (Claude)

- 검토 일시: 2026-10-19 새벽
- 검토 환경: 데모 모드(`?demo=1`), 내장 브라우저 375×812 전 화면 캡처 + 1280 일부, 코드·스타일 캐스케이드 정독. 실서버(회장 로그인)는 보지 않음.
- 검토 범위: 홈·투표·매칭·배정표·장부·내 현황·회칙·도움말·관리(멤버/투표/매치), `docs/guide.md`, `DESIGN.md`, `PRODUCT.md`.
- 방법: 디자인 컨셉 검토(DESIGN.md 조항 대조)와 사용성 검토(팀원 30초 흐름·회장 주간 루프)를 각각 독립 에이전트로 돌린 뒤, "상" 등급 주장은 코드로 재확인하고 화면 캡처 소견을 합쳤다. Codex 보고서(`017-codex-ux-review.md`)는 보지 않고 썼다.

## A. 요약

1. **10/18에 넣은 가독성 변경 다수가 DESIGN.md 규칙과 충돌한다.** 보드 제목 22~28px(글자 크기 3종 규칙), 참석 칩 초록 워시(점등은 "할 일"에만), 취소·삭제 점선 버튼 나란히(파괴 버튼은 혼자), 표 머리글의 × 버튼(버튼 치수 2종·터치 44px). 이들은 회장이 직접 요청한 것이라 **"규칙을 고칠지, 화면을 되돌릴지"를 정해야** 한다(§F 결정 요청).
2. **사용성 "상" 5건은 10/18 변경과 무관한 기존 흐름의 구멍이다.** (1) 특별 투표가 토요일보다 앞서면 공유 링크가 특별 투표에 착지해 정기 투표가 미투표로 남음, (2) 투표 취소가 확인 없이 즉시 실행되고 되돌릴 곳이 화면에 없음, (3) 출석 기록이 "경기 완료 + 스코어 입력" 뒤에만 열림(가이드와 반대), (4) 매칭 카드에서 상태 버튼 한 번에 관리 패널이 닫힘, (5) 가이드가 약속한 "확정 시 구장비 자동 기록"이 코드에 없음.
3. 전체 인상: 부품·색·보드 언어는 잘 유지되고 있고 즉시 저장·즉시 반영 원칙은 코드가 충실히 지킨다. 문제는 **회장 루프의 이음새**(확인창·재펼침·연결 id)와 **규칙 문서와 화면의 불일치**다.

## D. 잘 된 점 (유지)

1. **즉시 저장·즉시 반영**: 참석/불참·연락 상태 버튼이 누르는 순간 저장되고 `aria-pressed` 검정 반전과 현황 칩이 같은 렌더에서 갱신된다. 원칙 1의 정석.
2. **삭제 안전장치**: 확인창에 함께 지워지는 투표·벌금·매치 건수와 "이번 경기를 안 하는 것이면 취소를 쓰세요" 권고, 정산된 벌금 연결 시 거부. 회장 교대 뒤에도 실수 복구 가능.
3. **개인정보 격리**: 회장 패널 DOM을 팀 화면에 만들지 않고 연락처·계좌는 관리 표에서만. 원칙 3.
4. **실패 격리와 폴백**: 매치 조회 실패가 투표를 막지 않고, 홈은 부분 실패를 따로 표시하며, 클립보드 실패 시 prompt 폴백. 10/18의 "경기 일시" 줄도 이 패턴을 따랐다.
5. **보드 언어와 점등 규칙의 정석 부분**: 미투표에만 켜지는 점, 진행 중 상태 칩만 점등, 마감/예정/취소의 그레이스케일 처리, 회장 도구의 행 부품 + 깊은 링크("관리 → 투표"). 수정 중 희석하지 말 것.

## E. 확인하지 못한 것

- 카톡 인앱 WebView에서 클립보드·`prompt` 폴백·`sms:` 링크·`<dialog>`·localStorage 유지(가이드 "다시 묻지 않습니다")의 실제 동작.
- 실서버 회장 로그인이 필요한 동작: 투표 삭제, 취소 투표 재생성, 열 추가(마이그레이션은 10/18 적용 완료).
