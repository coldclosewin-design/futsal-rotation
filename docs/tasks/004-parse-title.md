# [004] 카페 글 제목 파서 + 후보 점수 함수

- 브랜치: `codex/004-parse-title`
- 의존: 001 (main에 머지됨)
- 예상 규모: M

## 배경
네이버 카페 풋매 게시판 글 제목에서 경기 날짜·요일·시간·포맷·구장을 뽑아 "토요일 오전, 시작 8시 우선"으로
후보를 정렬합니다 (`docs/PLAN.md` §3). 제목 포맷이 제각각이라 정규식 기반 best-effort 파서가 필요하며,
못 뽑은 필드는 `null`로 두고 대시보드에서 "미분류"로 보여줍니다. 실제 제목 60건이
`test/fixtures/cafe-titles.json`에 있습니다 (Claude가 수집, 수정 금지).

## 목표
- `parseTitle(subject, writeTs)` 가 아래 구조를 반환하고, `scoreCandidate(...)` 가 정수 점수를 준다.
- 두 함수 모두 브라우저 전역과 Node `require` 양쪽에서 쓸 수 있는 순수 함수다 (DOM·fetch 없음).

## 상세 요구사항

### 1. `parseTitle(subject, writeTs)` 반환값
```js
{
  date: "2026-10-17" | null,   // 경기 날짜 (KST 기준 YYYY-MM-DD)
  weekday: "토" | null,        // 월화수목금토일 한 글자. date가 있으면 date에서 계산한 값이 우선
  weekdayMismatch: boolean,    // 제목의 요일 표기와 date 계산 요일이 다르면 true
  startHour: 8 | null,         // 0~24 정수
  endHour: 10 | null,
  formats: ["5v5"],            // "5v5" | "6v6" | "기타" 의 배열, 없으면 []
  venue: "분당 마루공원",        // 토큰 제거 후 남은 문자열, 없으면 ""
  closed: boolean,             // 제목만으로 판단한 마감 여부
  ok: boolean                  // date와 startHour가 모두 있으면 true
}
```
`writeTs`는 ISO 문자열 또는 `Date` (글 작성 시각, 연도·월 추론 기준). 잘못된 값이면 현재 시각 사용.

### 2. 날짜 규칙
- 인식 패턴: `10/17`, `10.17`, `10. 14.`, `10월 17일`, `10월17일`, `2026.10.17`, `2026년 10월 16일`, `26.10.18`, `17일 (토)`, `18(일)`, `9일 금요일`, `오늘`, `금일`, `오늘(13)`.
- 연도: 명시되지 않으면 `writeTs`의 연도. 단, 파싱한 월이 `writeTs` 월보다 6 이상 작으면 다음 해(12월 글의 1월 경기).
- 일(日)만 있으면 월은 `writeTs`의 월. 단, 일이 `writeTs`의 일보다 3 이상 작으면 다음 달.
- `오늘`/`금일` → `writeTs`의 날짜. `오늘(13)` → 일 13 (위 규칙).
- 날짜 토큰은 시간 파싱 **전에** 제거한다 (`10/17`이 10시~17시로 오인되지 않게).
- 유효하지 않은 날짜(2월 30일 등) → `date: null`.

### 3. 요일 규칙
- 표기 인식: `(토)`, `(토요일)`, `토요일`, 공백으로 둘러싸인 단독 `토`, `화 ` 등 (월화수목금토일만).
- `date`가 있으면 `weekday`는 date에서 계산. 표기와 다르면 `weekdayMismatch: true` (date 우선).
- `date`가 없고 표기만 있으면 표기를 그대로 `weekday`에.

### 4. 시간 규칙
- 인식 패턴(시작-종료): `06-08시`, `08:00~10:00`, `8-10`, `8~10시`, `20-22`, `21시~23시`, `22시-24시`, `8시_10시`, `오전 8시 10시`, `오전10시-12시`, `8am~10am`, `21:00~ 23:00`, `19시-21시`, `저녁시간대(16~20)`.
- 단독 시작만: `21시`, `오후 8시`, `21:00` → `startHour`만, `endHour: null`.
- `오후`/`저녁`/`밤` 접두 + 12 미만 → +12. `오전` 또는 접두 없음 → 그대로. `pm` 접미 → +12 (12 미만일 때). 종료가 시작보다 작고 시작이 오후면 종료도 +12 (예: `오후 8시 10시` → 20, 22).
- `구장`, `호점`, `명`, `월`, `일`, `점` 바로 앞의 숫자는 시간이 아니다 (`2호점`, `3구장`, `1구장`, `제2풋살장`).
- 범위 밖(0~24 아님) → null.

### 5. 포맷 규칙
- `5:5`, `5vs5`, `5v5`, `5대5`, `5 대 5` → `"5v5"`; `6:6`, `6vs6`, `6v6`, `6대6`, `66매칭`, `66 매칭` → `"6v6"`; `9대9`, `7v7`, `8:8` 등 → `"기타"`. 여러 개면 모두 (순서는 제목 등장 순, 중복 제거).
- 시간 패턴(`22-24`)이 포맷으로 오인되지 않게 포맷은 시간 토큰 제거 후 검사하거나, 포맷 구분자(`:`, `vs`, `v`, `대`)가 붙은 경우만 인식한다. `66매칭`만 예외.

### 6. 마감 규칙
- `closed = /마감|완료|구함완료|모집완료|마감되었/.test(subject)`. 호출 측은 `headName === "매치마감"`도 함께 본다 (이 함수 밖).

### 7. `venue`
- 날짜·요일·시간·포맷 토큰을 제거하고, 다음 단어들도 제거: `매칭, 매치, 상대팀, 상대, 초청합니다, 초청드립니다, 초청, 구합니다, 구해요, 구해봅니다, 구함, 모십니다, 모셔요, 모집, 무료, 급구, 풋살, 팀, 합니다, 드립니다, 오늘, 금일`. 구두점(`/ , ! ~ ( ) [ ] _ -`)과 연속 공백 정리, 앞뒤 공백 제거. 완벽할 필요 없음.

### 8. `scoreCandidate(parsed, { headName, writeTs, now })` → 정수 또는 `null`
- `null` (목록에서 제외): `parsed.closed` 또는 `headName === "매치마감"` 또는 `parsed.date == null` 또는 `parsed.date < now의 날짜`.
- 기본: `weekday === "토"` → +100, 그 외 → −100.
- 시작 시간: 8 → +40, 7 → +30, 9 → +20, 10 → +10, 6 또는 11 → 0, 12 이상 → −100, `null` → −20.
- `formats`에 `"5v5"` 또는 `"6v6"` 포함 → +10.
- `writeTs`가 `now` 기준 24시간 이내 → +5.
- 숫자는 `EXICAN_CONFIG.PREFERRED_START_HOURS` 순서(8,7,9,10)와 일치해야 하며, 점수 상수는 파일 상단 `SCORE` 객체에 모아둔다.

### 9. export
```js
if (typeof module !== "undefined" && module.exports) {
  module.exports = { parseTitle, scoreCandidate, SCORE };
}
if (typeof window !== "undefined") { window.ExicanParse = { parseTitle, scoreCandidate, SCORE }; }
```

## 참고
- 픽스처의 `writeTs`는 `+09:00` 오프셋 ISO 문자열. 날짜 계산은 KST 기준으로 하되 `Date` 객체의 로컬 타임존에 의존하지 말고 문자열 연·월·일만 사용한다.
- 요일 계산은 `new Date(Date.UTC(y, m-1, d)).getUTCDay()` 로 타임존 영향 없이.
