# [019] 회장 루프 묶음 — 투표 취소 확인·복구, 펼침 상태 보존, 출석 폼 조건, 구장비 장부 기록, 전부 정산 확인

- 브랜치: `codex/019-president-loop`
- 의존: 018 (main에 머지된 뒤 시작)
- 예상 규모: M~L (M 항목 5개)

## 배경
017 검토(`docs/reviews/017-comparison.md` §5-2)에서 합의한 회장 주간 루프의 이음새 수정이다. 공통점은 "회장이 누른 뒤 다음 행동이 끊기거나, 되돌릴 길이 없거나, 문서가 약속한 자동화가 없다"는 것. 관련 설계 `docs/PLAN.md` §7.

## 목표
- 투표 취소는 확인을 거치고, 취소한 뒤 되돌릴 길이 같은 화면에 보인다.
- 매칭 관리 패널과 관리 출석 패널이 저장해도 닫히지 않는다.
- 경기일이 지난 매치는 상태와 무관하게 출석을 넣을 수 있고 스코어는 선택이다.
- 매치 확정 때 구장비를 장부에 바로 기록할 수 있다(가이드와 코드 일치).
- "전부 정산"은 금액·건수를 확인한 뒤 실행된다.

## 상세 요구사항

### 1. 투표 취소 확인과 복구
- `vote.html` 278행 `cancel` 핸들러: 취소(`checked === true`)일 때 `confirmDelete`와 같은 구조의 확인창(`#vote-dialog` 재사용)을 띄운다. 제목 "투표 취소", 본문 "10/25(토) 경기 투표를 숨깁니다. 투표·벌금 기록은 남고, 관리 → 투표에서 취소 해제할 수 있습니다. 이번 주 자동 생성은 이 날짜를 다시 만들지 않습니다.", 버튼 "닫기"(secondary) / "투표 취소"(btn-destructive). 취소 해제는 확인 없이 즉시.
- 취소 성공 뒤 `page-message`를 "10/25(토) 투표를 취소했습니다. 되돌리려면 **관리 → 투표**에서 취소 해제" + `admin.html?tab=polls` 링크(데모는 `&demo=1`)로 바꾸고, 다른 투표가 있으면 그 투표를 선택한다. 기존 "일요일 13:00에 자동 생성됩니다" 문구는 취소한 날짜가 이번 주 토요일일 때는 쓰지 않는다.
- `admin.html` 210행대 `data-cancel-poll`: 취소일 때 같은 확인창(`modal()` + `write()`), 토스트는 "투표를 취소했습니다" / "취소를 해제했습니다"로 구분.
- 삭제·취소 확인창의 닫기 버튼 라벨은 모두 "닫기"(현재 "취소"). `js/poll-form.js`의 "취소" 버튼도 "닫기"로.

### 2. 펼침 상태 보존
- `matches.html` `renderCards()`(365행): `const openAdmin = new Set()`을 두고 `<details>`의 `toggle` 이벤트에서 article id를 넣고 빼며, 재렌더 때 `details.open = openAdmin.has(id)`로 복원한다. 문자 미리보기 `<details class="sms-preview">`도 동일. 스크롤 위치는 브라우저가 유지하므로 별도 처리 없음.
- `admin.html` `refresh()`(143행) 뒤 렌더에서 `<details class="operations-attendance">`와 투표 카드의 "멤버별 투표 보기"도 같은 방식으로 열림을 복원한다.

### 3. 출석 폼 조건과 스코어
- `admin.html` 135행 조건을 `match.status === "played" || match.match_date <= today()`로. 예정 상태에서 출석을 저장해도 상태는 바꾸지 않는다(카드에 "출석을 저장해도 경기 상태는 그대로입니다. 끝났으면 상태를 경기 완료로 바꾸세요" 힌트 한 줄).
- `js/data-admin.js` 259행 "완료 경기의 스코어를 입력하세요": **둘 다 비어 있거나 둘 다 있어야** 통과로 완화. 한쪽만 있으면 기존 오류. 지난 경기 목록(`matches.html` 지난 경기 섹션, `describeHistory`)은 스코어가 없으면 "스코어 미입력"으로 보이는지 확인하고, 아니면 그 문구를 붙인다(`js/candidates.js` 출력 형식은 바꾸지 말고 호출부에서 처리).
- `docs/guide.md` 회장 편 "7. 경기 후"의 순서를 "출석 기록 → 벌금 생성 → (알면) 상태 경기 완료·스코어"로 고친다.

### 4. 매치 확정 시 구장비 장부 기록
- `matches.html` 매치 등록 모달(약 485~568행)에 체크박스 "구장비를 장부에 바로 기록(팀 지출)" 기본 켬. 구장비가 0이면 체크박스 비활성.
- 체크 상태로 등록 성공 시 `ExicanData.addLedger({ member_id: null, category: "venue_fee", amount: -cost, ref_match_id: savedMatch.id, settled: true, entry_date: match_date, note: "<구장> 구장비" })`를 호출한다. 행 구성은 `admin.html` "구장비 기록" 버튼(약 243행)과 **같은 필드**를 쓴다(그 코드를 참고해 맞춘다). 중복(23505)은 성공으로 취급(`admin.html` 184행 패턴). 실패하면 매치는 남기고 토스트 "매치는 등록됐지만 구장비 기록은 실패했습니다: …".
- 관리 → 매치의 "구장비 기록" 버튼은 그대로 둔다(중복은 이미 거부됨).
- `docs/guide.md` 회장 편 "4. 주중" 114·116행 문구를 실제 동작(체크박스, 중복은 자동 거부)으로 고친다.

### 5. 전부 정산 확인
- `ledger.html` 273행 `data-settle-member` 핸들러: 실행 전 확인창(기존 장부 모달 부품) "○○○ · 2026년 10월 · 미정산 2건 · 35,000원을 정산 완료로 바꿉니다." 버튼 "닫기" / "정산". `settle-selected`(선택 정산)도 같은 확인창에 건수·합계.
- 정산 되돌리기: 멤버 상세의 정산 완료 항목에 "정산 취소" 보조 버튼(36px, 회장만) → `setSettled(ids, false)`. 이미 `setSettled`가 boolean을 받으므로 데이터 계층 변경 없음.

## 수용 기준
- [ ] 투표 취소가 확인창을 거치고, 취소 뒤 투표 탭에 복구 안내 링크가 보인다. 관리 탭 토스트가 취소/해제를 구분한다.
- [ ] 매칭 관리 패널에서 상태 버튼을 눌러도 패널이 열린 채다. 관리 출석 저장 뒤 출석 패널이 열린 채다.
- [ ] 경기일이 지난 예정 매치에 출석 폼이 보이고, 스코어 없이 "경기 완료" 저장이 된다.
- [ ] 매치 등록 모달의 체크박스로 구장비가 장부에 `venue_fee` 음수 지출로 들어가고, 두 번 등록해도 한 번만 잡힌다.
- [ ] 전부 정산·선택 정산이 확인창을 거치고, 정산 취소가 된다.
- [ ] `docs/guide.md`의 세 문구가 실제 동작과 같다. `npm test` 통과.
