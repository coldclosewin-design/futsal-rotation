## 상세 요구사항

### 1. 검토 기준 (이 순서로 본다)
1. **디자인 컨셉 이탈** — `DESIGN.md`의 Do's and Don'ts, "페이지 구조 규칙", "부품 통일 규칙"과 비교. 특히: 강조색은 `--lit` 하나만 상태 표시에 소량(그레이스케일 + 강조색 1개, `PRODUCT.md` Brand Commitments), 버튼은 44/15 + 보조 36/12 둘뿐, 선택 스트립 한 부품, 보드(전광판)는 날짜·숫자·상태만, 패널 알파 .78, 점등 점 8px, 날짜 형식 "10/17 토".
2. **사용성 저하** — `PRODUCT.md` Product Principles 1~5와 Accessibility(375px 가로 스크롤 금지, 터치 44px, 명도 대비 AA). 팀원 30초 흐름(링크 열기 → PIN → 이름 → 참석 → 닫기)과 회장 주간 루프(일 투표 공유 → 월 마감 확인 → 주중 매칭 → 토 배정표 → 경기 후 출석·벌금 → 월초 정산)를 **실제로 데모에서 끝까지 수행**하며 막히는 곳, 헷갈리는 문구, 불필요한 단계, 눈에 안 띄는 중요 정보를 적는다.
3. **개선안** — 위 두 기준과 무관하더라도 팀원·회장이 더 편해지는 안. 기존 부품으로 구현 가능한 것을 우선한다.
